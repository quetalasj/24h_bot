Ты — опытный Python-разработчик, специализирующийся на асинхронных Telegram-ботах и библиотеке aiogram 3.x.

Сгенерируй полный, готовый к запуску код простого Telegram-бота для управления таймерами.
Пользователь запускает таймер командой, например /timer 10m. Бот подтверждает установку, ждёт указанное время и по его истечении сам отправляет сообщение «Время вышло!».

## Требования к результату

Создай один файл `bot.py`, содержащий:
- полный исходный код бота;
- понятные комментарии на русском языке;
- код, готовый к запуску после установки зависимостей и указания токена.
- используй pixi для созданий virtual environment (https://pixi.prefix.dev/)

Также добавь в ответ:
- `pixi requirements` файл в соответствующем формате;
- краткую инструкцию по запуску;
- указание, где получить и вставить Telegram Bot API token.

## Технологии

- Python 3.11
- aiogram 3.7 или выше (используй актуальный синтаксис aiogram 3, а не устаревший aiogram 2)
- asyncio
- Только стандартная библиотека Python и aiogram
- Без базы данных, ORM, Redis, внешних сервисов и планировщиков задач
- Используй .env файл для задания переменных окружения;


## Функциональность бота

0. При первом подключении к боту он должен вывести все доступные команды с примерами и описанием.

1. Команда `/timer 10m`:
   - принимает длительность в формате `<число><единица измерения>`;
   - поддерживает минимум: `s` — секунды, `m` — минуты, `h` — часы, 'd' - дни;
   - пример: `/timer 10m`, `/timer 30s`, `/timer 1h`, `/timer 2d`;
   - пробелы между числом и еденицей должны быть автоматичеки проигнорированы;
   - при корректном вводе запускает таймер;
   - отвечает пользователю: `Таймер на 10 минут установлен`;
   - текст должен корректно отображать выбранную длительность.

2. Команда `/cancel`:
   - отменяет активный таймер пользователя;
   - отвечает: `Таймер отменён`;
   - если активного таймера нет, отвечает понятным сообщением об этом.

3. По истечении времени таймера:
   - бот автоматически отправляет пользователю сообщение: `Время вышло!`.

4. Команда `/logs n`:
   - выводит последние `n` команд пользователя который оптравил запрос (ответ должен сосоять из `команды`, `текущего состояния` и `результата её выполнения`, а так же ошибки если есть; логи не должны содержать никакой конфиденциальной информации);
6. Команда /help:
   - выводит все доступные команды с примерами на каждую.



## Правила хранения состояния

- Храни активные таймеры только в оперативной памяти.
- Используй словарь или другую подходящую in-memory структуру.
- Ключом должен быть идентификатор пользователя.
- При перезапуске бота таймеры могут теряться — это допустимо.
- Не используй файлы, SQLite, PostgreSQL, Redis или любые другие постоянные хранилища.
- Для каждого пользователя храни запись, содержащую как минимум:
  - `asyncio.Task`;
  - время окончания таймера;
  - исходную длительность.
- При запуске нового таймера сначала отмени предыдущую задачу пользователя, затем запусти новую.
- Для отмены используй `asyncio.Task.cancel()`.
- Не подавляй `asyncio.CancelledError`.
- В корутине таймера используй `try/finally`, чтобы гарантированно удалить запись пользователя из хранилища.
- После успешной отмены удаляй запись из словаря и отправляй: `Таймер отменён`.
- Если у пользователя нет активного таймера, отправляй: `Активный таймер не найден`.

## Технические требования к реализации

- Используй асинхронный код.
- Для ожидания окончания таймера используй `asyncio.sleep()` или `asyncio.create_task()`.
- Не используй блокирующий `time.sleep()`.
- Обеспечь возможность отмены задачи таймера через `asyncio.Task.cancel()` или эквивалентный корректный механизм.
- Корректно обрабатывай несколько пользователей: таймеры разных пользователей не должны конфликтовать.
- Если пользователь запускает новый таймер, пока предыдущий активен, отмени старый и запусти новый.
- Валидируй аргумент команды `/timer`:
  - если аргумент отсутствует или имеет неверный формат, отправь понятную подсказку с примерами;
  - не допускай отрицательных, нулевых или чрезмерно больших значений; выбери разумный максимальный предел, например 24 часа.
- Обрабатывай возможные ошибки запуска бота и некорректный токен понятным сообщением.
- Токен бота читай из переменной окружения `BOT_TOKEN`, а не храни его в коде.

## Надёжность и логирование

- Настрой стандартный модуль `logging` с уровнем `INFO`.
- Логируй запуск таймера, отмену, завершение и ошибки отправки сообщений.
- Если отправка `Время вышло!` не удалась, логируй ошибку, но не завершай работу бота.
- Если переменная окружения `BOT_TOKEN` отсутствует, выведи понятное сообщение об ошибке и заверши программу с ненулевым кодом выхода.
- Логи должны быть помечены так, чтобы можно было определить к какому пользователю они относятся.


## Архитектура и качество кода
